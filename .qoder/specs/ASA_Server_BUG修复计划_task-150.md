# ASA Server Manager 代码审查与BUG修复计划

## 背景
用户请求检查项目中的功能性问题与BUG。经过对关键代码文件的全面审查，发现了多个潜在问题，包括并发安全、资源泄漏、错误处理、状态管理等方面的问题。

## 发现的问题与修复方案

### 1. 并发安全问题

#### 1.1 waitServerStartup 中的竞态条件
**文件**: `asaserver/common.go` 第680-718行
**问题**: `latestLogLine` 变量在 goroutine 和回调函数中被访问，但只有部分地方使用了锁保护。
**影响**: 可能导致数据竞争和不可预测的行为。
**修复方案**: 确保所有对 `latestLogLine` 的访问都在 `latestLogLineMu` 锁保护下进行。

#### 1.2 handleServerUpdate 中的竞态条件
**文件**: `webapi/api.go` 第602-654行
**问题**: `updateBroadcaster.Start()` 在锁内调用，但 `runUpdateTask` 在锁外启动，可能存在竞态条件。
**影响**: 可能导致多个更新任务同时运行。
**修复方案**: 将 `go s.runUpdateTask(ctx)` 移到锁内，或使用原子操作确保只启动一个任务。

### 2. 资源泄漏问题

#### 2.1 TailLogFileWithLines 中的 context 泄漏
**文件**: `asaserver/common.go` 第82-182行
**问题**: 如果 `readLastNLines` 失败，函数会返回，但 `cancel` 函数不会被调用。
**影响**: 可能导致 context 和相关资源泄漏。
**修复方案**: 在函数开头使用 `defer cancel()` 确保 cancel 总是被调用。

#### 2.2 SSE 流中的 goroutine 泄漏
**文件**: `webapi/api.go` 第1004-1037行
**问题**: 如果 `logChan` 发送阻塞，可能会导致 goroutine 泄漏。
**影响**: 长期运行可能导致内存泄漏。
**修复方案**: 增加 `logChan` 的缓冲区大小，或使用非阻塞发送。

### 3. 错误处理问题

#### 3.1 StopServer 状态回滚不完整
**文件**: `asaserver/server.go` 第551-663行
**问题**: 如果 `SaveWorldSafely` 失败，函数会返回错误，但状态可能没有正确回滚。
**影响**: 实例可能停留在错误状态。
**修复方案**: 在 defer 函数中添加更完整的状态回滚逻辑。

#### 3.2 UpdateInstanceConfig 空字符串处理
**文件**: `asaserver/config.go` 第244-293行
**问题**: `copier.CopyWithOption` 使用 `IgnoreEmpty: true`，空字符串不会被更新。
**影响**: 某些字段无法被清空（如 ServerPassword）。
**修复方案**: 对于需要清空的字段，单独处理。

### 4. 状态管理问题

#### 4.1 recoverStuckStates 中的长时间持锁
**文件**: `asaserver/state_manager.go` 第617-652行
**问题**: 在锁内调用 `isInstanceProcessAlive`，后者会执行外部命令。
**影响**: 可能导致死锁或长时间持锁。
**修复方案**: 先在锁内收集需要检查的实例列表，然后释放锁后再检查进程状态。

### 5. WebSocket 广播问题

#### 5.1 sendEventToAll 中的连接清理
**文件**: `httpserver/hub.go` 第124-146行
**问题**: 如果 `WriteJSON` 失败，连接没有被移除。
**影响**: 后续广播可能继续失败。
**修复方案**: 在 `WriteJSON` 失败时移除连接。

### 6. 备份恢复问题

#### 6.1 RestoreBackupToInstance 部分恢复
**文件**: `backup/backup.go` 第162-293行
**问题**: 如果恢复过程中出错，已经创建的文件不会被清理。
**影响**: 可能导致部分恢复的状态。
**修复方案**: 添加事务性恢复，出错时回滚已创建的文件。

### 7. 日志监控问题

#### 7.1 TailLogFileWithLines 文件截断处理
**文件**: `asaserver/common.go` 第82-182行
**问题**: 文件被截断时，从开头重新读取，但不通知调用方。
**影响**: 可能导致日志重复或丢失。
**修复方案**: 添加文件截断检测和通知机制。

### 8. 安全问题

#### 8.1 RCON 密码日志泄露
**文件**: `asaserver/server.go` 第792行
**问题**: RCON 连接失败时，错误日志中包含了 RCON 密码。
**影响**: 安全风险。
**修复方案**: 从日志中移除密码信息。

### 9. 进程管理问题

#### 9.1 ForceStopServer 错误处理
**文件**: `asaserver/server.go` 第666-686行
**问题**: 如果 `LoadInstanceConfig` 失败，函数继续执行但不返回错误。
**影响**: 可能导致静默失败。
**修复方案**: 改进错误处理逻辑。

### 10. 配置同步问题

#### 10.1 SyncInstanceConfigFromSource 部分同步
**文件**: `asaserver/config.go` 第543-638行
**问题**: 复制文件过程中出错，已复制的文件不会被清理。
**影响**: 可能导致配置不一致。
**修复方案**: 添加事务性同步，出错时回滚。

## 验证方案

1. **并发安全**: 使用 `go test -race` 运行测试，检查是否有数据竞争。
2. **资源泄漏**: 使用 `go tool pprof` 检查内存使用情况。
3. **错误处理**: 模拟各种错误场景，验证状态回滚。
4. **状态管理**: 测试长时间运行的状态管理器。
5. **WebSocket**: 测试大量并发连接和断开。
6. **备份恢复**: 测试恢复过程中断的情况。
7. **日志监控**: 测试日志文件截断和轮转。
8. **安全**: 检查日志文件中是否包含敏感信息。
9. **进程管理**: 测试进程异常退出的情况。
10. **配置同步**: 测试同步过程中断的情况。

## 实施步骤

1. 首先修复高优先级的并发安全和状态管理问题。
2. 然后修复资源泄漏和错误处理问题。
3. 最后修复其他低优先级问题。
4. 为每个修复添加单元测试。
5. 运行完整的测试套件验证修复效果。
6. 更新相关文档。

## 风险评估

- **并发安全修复**: 可能影响性能，需要仔细测试。
- **状态管理修复**: 可能改变现有行为，需要全面测试。
- **资源泄漏修复**: 低风险，但需要验证不会引入新的泄漏。
- **错误处理修复**: 可能改变错误处理流程，需要测试各种场景。

## 结论

项目存在多个功能性问题和BUG，需要系统性地修复。建议按照优先级逐步修复，并添加充分的测试来验证修复效果。
